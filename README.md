# meter-reader

Распознаёт показания счётчиков воды по фото с ESP32-CAM и отправляет их в Home Assistant.

```
ESP32-CAM (ESPHome)                 meter-reader (Docker)                    Home Assistant
вспышка + снимок  ◄── HTTP ───  по расписанию: вспышка → снимок →  ── MQTT ──►  сенсор «Показание»
                                нейросети AI-on-the-edge → проверки              (панель «Энергия»)
```

Камера только фотографирует, поэтому подходит любая ESP32-CAM, даже с 2 МБ PSRAM. Распознавание работает
на моделях и по алгоритму [AI-on-the-edge-device](https://github.com/jomjol/AI-on-the-edge-device), включая
цифры «между» положениями барабана и красные стрелки.

## 1. Камера (ESPHome)

1. Скопируйте `esphome/water-cam.yaml` для каждого счётчика и поменяйте `name` (например, `water-cam-hot`).
2. Создайте `secrets.yaml` по образцу `esphome/secrets.yaml.example`.
3. Первая прошивка — по USB (через плату ESP32-CAM-MB), дальше — по воздуху.
   Командой `esphome run water-cam-cold.yaml` (например, `pip install esphome` или контейнер
   `ghcr.io/esphome/esphome`).
4. Закрепите за камерой постоянный IP (резервирование DHCP на роутере).
5. Подкрутите объектив под расстояние до счётчика: с завода он сфокусирован на бесконечность.

HA сам найдёт камеру как ESPHome-устройство. Добавлять её не обязательно: тогда в HA будут видны камера и вспышка.

## 2. Сервер

Задайте `UI_PASSWORD` в `docker-compose.yml`, затем:

Готовый образ: `ghcr.io/slavmak/meter-reader:latest`. Его собирает GitHub Actions при каждом push в `main`.
На сервере достаточно `docker-compose.yml`:

```sh
docker compose pull && docker compose up -d   # установить или обновить из реестра
docker compose up -d --build                  # или собрать из исходников
```

Веб-интерфейс откроется на `http://<сервер>:8000`.

**Архитектура:** опубликованный образ собран только под **x86_64 (amd64)**. Для arm64 (Raspberry Pi 4/5 с
64-битной ОС) соберите образ из исходников на самом устройстве или добавьте `platforms: linux/amd64,linux/arm64`
в `.github/workflows/docker.yml` (вместе с `docker/setup-qemu-action`). Под 32-битную Raspberry Pi OS нет
сборок `ai-edge-litert`.

## 3. MQTT

Нужен уже работающий брокер (Mosquitto), к которому подключён Home Assistant.

1. Заведите в брокере пользователя для meter-reader, например `mosquitto_passwd /mosquitto/config/passwd meter-reader`.
2. В веб-интерфейсе, блок **MQTT**: сервер, порт, пользователь, пароль → **Сохранить**. Рядом с заголовком
   появится статус: «подключено» или текст ошибки, например «Not authorized».

Пароль хранится в `data/config.json` и обратно в браузер не отдаётся: пустое поле значит «оставить
сохранённый». Сервер брокера указывайте по IP, а не `localhost`: внутри контейнера `localhost` — это сам
контейнер.

## 4. Настройка в веб-интерфейсе

1. **+ Счётчик** → id (`cold`, `hot`), укажите IP камеры → **Сохранить**.
2. **📷 Снимок**. Если цифры наклонены, задайте **Поворот** так, чтобы ряд цифр стал горизонтальным.
3. Режим **цифра**: обведите каждый барабан **слева направо**, включая красные (литры). Удобно сначала
   обвести первую цифру, потом нажимать **Дублировать →** и **Выровнять цифры**.
4. Режим **стрелка**: обведите круглые шкалы, начиная со старшей (×0.1, потом ×0.01 и т. д.).
   Если стрелка крутится против часовой, отметьте ↺.
5. **Распознать**: над каждой областью появится значение, внизу — итоговая строка.
6. **Сдвиг запятой**. Значение составляется так: `цифры.стрелки`, потом запятая сдвигается. Примеры:

   | Счётчик | Области | Сдвиг |
   |---|---|---|
   | 5 чёрных + 3 красных барабана | 8 цифр | `-3` |
   | 5 чёрных барабанов + 4 стрелки | 5 цифр, 4 стрелки | `0` |
   | 5 чёрных + 3 красных + 1 стрелка | 8 цифр, 1 стрелка | `-3` |

7. **Сохранить** → **Считать и отправить в HA**.

В HA появится устройство с сенсорами «Показание» (м³), «Распознано» и «Ошибка».
Чтобы добавить счётчики в панель «Энергия»: **Настройки → Панели → Энергия → Потребление воды**.

## Проверки и настройки

- Показание **не может уменьшаться**, а расход выше **Макс. расход** (по умолчанию 3 м³/ч) отбрасывается.
  В обоих случаях в HA остаётся предыдущее значение, а причина видна в сенсоре «Ошибка».
- Нераспознанная цифра (`N`) подставляется из предыдущего показания. Самое первое показание должно
  распознаться целиком.
- **Интервал**: даже если нужен учёт раз в день, ставьте 15–60 минут. Чем чаще снимки, тем лучше
  работают проверки, а нагрузка мизерная.
- Блики от вспышки: уменьшайте **Вспышку** (20–80 из 255) и **Паузу** подбирайте так, чтобы экспозиция
  успела подстроиться.
- **Переход стрелка→цифра** (9.2) — порог AI-on-the-edge `AnalogToDigitTransitionStart`. Его стоит менять,
  только если последняя цифра перескакивает раньше или позже стрелки.

## Чего нет (пока)

- Выравнивания по опорным меткам: камера должна быть закреплена жёстко.
- Архива снимков: хранится только последний (`data/<id>.jpg`).
- Режимов AI-on-the-edge `ContinuousLastDigit`, `ExtendedResolution`, `CheckDigitIncreaseConsistency`.
