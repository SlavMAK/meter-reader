# Ход работы (последнее обновление 2026-11-05)

## Цель
ESP32-CAM на счётчиках горячей и холодной воды делает снимок со вспышкой. Сервер meter-reader в Docker
распознаёт цифры и стрелки моделями AI-on-the-edge и отправляет показания в Home Assistant через MQTT.

## Принятые решения (и почему)
- **Не AI-on-the-edge на плате:** у нашей ESP32-CAM PSRAM `ESP PSRAM16M` = 2 МБ, а прошивке нужно ≥ 4 МБ.
  Плата только снимает (ESPHome), распознавание идёт на сервере.
- **Распознавание:** порт алгоритма AI-on-the-edge на Python (`reader/recognize.py`). Сверен с векторами
  из их юнит-тестов (`reader/test_recognize.py`). Модели по умолчанию: `dig-cont_0900_s3_q`, `ana-cont_1500_s2_q`.
- **Передача в HA:** MQTT discovery, не эмуляция ESPHome API (aioesphomeserver отвергнут: сырой проект).
- **MQTT-брокер:** у пользователя уже есть Mosquitto на сервере. Настройки брокера вводятся в веб-интерфейсе
  (блок MQTT) и хранятся в `data/config.json`. Пароль в браузер не отдаётся.
- **HA работает в Docker** (не HA OS), поэтому аддон не нужен, meter-reader — отдельный контейнер.
- Лицензия AI-on-the-edge: только личное некоммерческое использование (`LICENSE-AI-on-the-edge.md`).

## Железо
- ESP32-CAM AI-Thinker, чип ESP32-D0WDQ6 rev 1.0, MAC `4c:eb:d6:7c:d2:8c`, флеш 4 МБ, PSRAM 2 МБ.
- Камера инициализируется (в первый раз была ошибка `camera not supported` — помогло переподключить шлейф).
  Модель сенсора по надписи на шлейфе пока не уточнена.
- **Сеть:** имя `water-cam-cold`, IP **192.168.0.102** (стоит закрепить в DHCP роутера).
  Ноутбук — 192.168.0.148.
- **Питание:** лабораторный блок 5.0 В, ограничение ~1 А, к выводам 5V/GND. От USB через Arduino был
  brownout-цикл при старте Wi-Fi. Причина — просадка на тонких проводах.
- **Прошивка по USB** (нужна только в первый раз или если OTA сломается): Arduino Uno без чипа как UART,
  `/dev/ttyACM0`. Подключение: Arduino 0(RX)→U0R, 1(TX)→U0T (прямо, не крест-накрест), GND→GND,
  перемычка IO0–GND и нажатие RST для режима прошивки.
- Дальнейшие прошивки идут **по Wi-Fi (OTA)**.

## Прошивка камеры (`esphome/water-cam.yaml`)
- web_server :80 (вспышка `POST /light/Flash/turn_on?brightness=N`), снимок `http://<ip>:8081/`.
- Вспышка GPIO4 через ledc (канал 2, 20 кГц), сама гаснет через 15 с.
- Светодиод состояния GPIO33 (`status_led`): короткая вспышка раз в 3 с — всё в порядке; частое мигание —
  Wi-Fi или ошибка; горит постоянно или не горит — зависла или нет питания.
- `api: reboot_timeout: 0s`: иначе плата перезагружалась бы каждые 15 мин без подключения HA.
- `esphome/secrets.yaml` содержит пароль Wi-Fi, его не публиковать.

## Полезные команды
```sh
docker compose up -d --build                # запустить или обновить сервер (из корня проекта)
docker compose logs -f                      # логи сервера
docker compose down                         # остановить
cd esphome && uvx esphome run water-cam.yaml --device 192.168.0.102   # собрать и прошить по OTA
uvx esphome logs water-cam.yaml --device 192.168.0.102                # логи камеры по Wi-Fi
cd reader && python test_recognize.py       # тесты распознавания
```
Если проверяете вспышку через curl, добавьте `-d ""`: без тела ESPHome отвечает `411 Length Required`.
